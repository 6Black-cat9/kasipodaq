# Қауіпсіздік тәртібі

## Сессия және пароль

Парольдер bcrypt арқылы 12 rounds-пен hash жасалады. Жаңа пароль кемінде 8
таңба болуы және UTF-8 форматында 72 байттан аспауы керек; кіру және пароль
өзгерту де осы байт шегін тексереді. Пароль hash-і API жауаптарына кірмейді.

JWT тек HS256 алгоритмімен тексеріледі және 8 сағатқа беріледі. Браузер
сессиясы `HttpOnly`, `SameSite=Lax` cookie-де сақталады; production cookie
`Secure` болады. Әр қорғалған сұрау дерекқордағы `isActive`, рөл және
`tokenVersion` мәндерін тексереді. Шығу, парольді өзгерту, рөлді өзгерту және
аккаунтты бұғаттау бұрынғы сессияларды жарамсыз етеді. REST клиенттері JWT-ді
`Authorization: Bearer` арқылы да бере алады.

`CLIENT_URL` — рұқсат етілген origin тізімі; бірнеше мекенжай үтірмен
бөлінеді. CORS осы тізімді қолданады және барлық жазу API сұрауларындағы
браузер Origin мәнін тексереді. Origin жібермейтін REST клиенттері JWT
тексеруінен өтеді.

## Рұқсаттар

| Модуль | MEMBER | CHAIRMAN | ADMIN |
| --- | --- | --- | --- |
| Өз профилі және пароль | Басқару | Басқару | Басқару |
| Өтініштер | Тек өз өтініштері | Барлығын қарау, жауап беру | Барлығын басқару |
| Мүшелер | Рұқсат жоқ | Көру | Басқару |
| Жаңалықтар, іс-шаралар | Жария деректерді көру | Басқару | Басқару |
| Құжаттар | Көру, жүктеу | Көру, жүктеу | Басқару |
| Статистика | Рұқсат жоқ | Көру | Көру |
| Қолданушылар, рөлдер, баптаулар | Рұқсат жоқ | Рұқсат жоқ | Басқару |

Мүшенің `INACTIVE` статусы аккаунтты бұғаттамайды: профиль мен бұрынғы
өтініштерді оқуға болады. Жаңа өтініш беру, өтінішті өзгерту, оған файл қосу
және іс-шараға тіркелу үшін белсенді мүшелік қажет. `User.isActive=false`
жүйеге кіруді және қорғалған сұрауларды тоқтатады. Ашық self-registration жоқ;
тіркеуді әкімші орындайды.

Өтініш, хабарлама және өтініш файлдарының иесі серверде тексеріледі.
Мүшелер басқа мүшелердің тізімін немесе жеке өтініштерін алмайды. Draft және
болашақ жариялану күні қойылған жаңалықтар тек әкімшілікке көрінеді.

## Файлдар

Бір сұрауда бір файл және ең көбі 10 МБ қабылданады. Рұқсат етілген түрлер:
PDF, DOC, DOCX, XLS, XLSX, JPG/JPEG, PNG. Extension, MIME және мазмұнның magic
signature сәйкестігі тексеріледі; қате detector жауабы 400 қатесіне айналады.
Құжат ZIP контейнерлері DOCX/XLSX ретінде анықталуы керек. Бөлек сурет upload
endpoint-і тек JPG және PNG қабылдайды.

Файл атауы серверде UUID арқылы жасалады, клиент жолы файл жүйесі жолына
айналмайды. Қорғалған файлдар жалпы static каталог арқылы берілмейді.
`/api/uploads/:filename` файлдың дерекқордағы мақсатын және пайдаланушының
рұқсатын тексереді. Өтініш файлдары иесіне және әкімшілікке ғана беріледі;
жария құжаттар мен жария контент суреттері ашық оқылады. Файл жауаптарында
`nosniff`, CSP sandbox және жеке файлдар үшін `no-store` қолданылады. Office
файлдары жүктеу ретінде беріледі.

## Деректердің тұтастығы

Zod schema сұрау өрістерін, enum мәндерін, мәтін ұзындығын және сомаларды
тексереді; күтпеген body өрістері қабылданбайды. Prisma параметрленген
сұрауларды қолданады. Клиент жаңалық пен өтініш мәтінін React мәтіні ретінде
көрсетеді.

Өтініш статусы, оның тарихы, жауап және хабарлама бір транзакцияда сақталады.
Статус қатар өзгергенде шартты update 409 қатесін береді. Мүше өзгерткен
өтініш және қосқан файл да рұқсат етілген ағымдағы статуспен тексеріледі.
Әкімші рөлін өзгерту мен әкімшіні жою бір PostgreSQL advisory lock қолданады,
орындаушының әкімші құқығын қайта тексереді және соңғы белсенді әкімшіні
сақтайды. Әкімші өз аккаунтын бұғаттай немесе жоя алмайды.

## HTTP және қателер

Helmet HTTP қауіпсіздік header-лерін орнатады. Жалпы API лимиті — бір IP үшін
минутына 240 сұрау; кіру лимиті — 15 минутта 15 әрекет. Тест режимінде ғана
лимиттер өшіріледі. JSON body лимиті — 1 МБ. `TRUST_PROXY=1` орнатылмаса,
сервер сырттан берілген proxy IP header-леріне сенбейді.

Global error handler бірізді `{success:false,message,errors}` жауабын береді;
пароль, JWT secret, stack trace және дерекқордың ішкі қатесі жауапқа кірмейді.
`/api/health` дерекқорға нақты сұрау жасайды. OpenAPI схема мен Swagger UI
`/api/openapi.json` және `/api-docs` жолдарында жарияланған.

Production талаптары мен орналастыру командалары:
[DEPLOYMENT.md](./DEPLOYMENT.md). Демо аккаунт парольдері production орнатуда
өзгертіледі; `.env` файлдары Git пен Docker build context-іне қосылмайды.
